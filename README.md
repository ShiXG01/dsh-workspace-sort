# dsh-workspace-sort

按「最近一次对话」排序 DSH 的工作区，并支持工作区置顶。

- **按时间排序**：工作区按组内最近一次会话活动（就是侧栏行上显示的
  「刚刚 / 15分钟 / 2小时」那个时间）从新到旧排列。
- **工作区置顶**：置顶的工作区整体排在未置顶工作区之前；多个置顶工作区之间
  仍按时间排序。
- **工作区排序方式**：在侧栏的视图选项菜单里选择 `手动排序` 或 `最近更新`；
  只有选 `最近更新` 才会自动重排（默认 `手动排序`，即自动排序默认关闭）。

## 排序规则

```
score(工作区) = 该工作区内所有「合格会话」的 updatedAt 最大值
合格会话 = 有摘要 ∧ 不是 subagent 会话 ∧ 不在归档集合 ∧ 不是空白会话

最近更新模式 = [置顶工作区按 score 降序] ++ [未置顶工作区按 score 降序]
手动排序模式 = [置顶工作区(保持原相对顺序)] ++ [未置顶工作区(保持原相对顺序)]
```

- 空工作区（没有合格会话）沉到所属分组最后，并保持彼此原有的相对顺序。
- score 相同时保持原有相对顺序。
- **默认是「手动排序」**，即自动排序默认关闭。
- 在**最近更新**模式下，只有排序键真的变化时才重排：你手动拖拽的结果会被保留，
  直到某个会话产生了新活动。
- 在**手动排序**模式下完全不按时间重排，但**置顶仍然立即生效**（置顶是显式指令）；
  取消置顶只移除标记、不恢复记忆位置，与会话级置顶的既有规则一致。

## 界面

| 位置 | 作用 | 实现 |
| --- | --- | --- |
| 视图选项菜单（「分组方式」下方、「排序方式」上方） | 「工作区排序方式」：手动排序 / 最近更新。仅在分组方式为**按工作区**或**按工作区树**时出现；单列表模式没有工作区行，因此不显示 | DOM 增强 |
| 工作区行尾图钉 | 一键置顶 / 取消置顶。未置顶时悬停行才显示（倾斜灰色），置顶后常驻并直立高亮（平底正立实心蓝），带即时乐观响应与过渡动画 | DOM 增强 |
| 工作区分割线 | 当存在置顶工作区时，在最后一个置顶工作区（及其子会话）与首个未置顶工作区之间自动渲染横向分割线 | DOM 增强 |
| 工作区行右键菜单 | 置顶此工作区 / 取消置顶 / 按最近更新排序 | DOM 增强 |
| 侧栏底部按钮 → 控制面板 | 完整替代入口：排序方式、逐个置顶、立即排序 | **官方 slot**（`sidebar.footer.action`）+ 自管容器 |

视图选项菜单与工作区行都没有官方插槽，所以前两项是 DOM 增强：

- 排序方式分组**克隆原生的 `手动排序` / `最近更新` 行作为模板**，因此外观、间距与文案
  语言都跟随原生；只有分组标题由插件本地化（中/英）。
- 行尾图钉被插进**该行原生的操作容器**（就是放「⋯」和「新建会话」按钮、且默认
  `display:none`、悬停才显示的那个）的**首位**，所以它天然继承原生的悬停显示、间距与
  对齐；找不到该容器时退化为直接挂在该行末尾，并使用插件自己的悬停显示规则。
- 图钉是**幂等补齐**的：React 重渲染若移除了它、或把它挤出了操作容器，下一次 DOM 变更
  就会把它放回原位。
- 底部面板反过来只依赖官方 slot，因此**即使所有 DOM 增强在未来的 DSH 版本里失效，
  置顶与模式切换依然可用**。面板本体是插件自己管理的容器（不在 React 树里），不会被
  重渲染清掉。

## 架构

| 半侧 | 职责 |
| --- | --- |
| `lib/index.js`（宿主） | 只拥有插件自身的持久状态（排序模式 + 置顶集合），通过带 fence 的 `/workspace-sort/api` 路由提供给浏览器；**不持有任何会话或工作区数据** |
| `lib/client.js`（浏览器，由 `order.cjs` + `menu.cjs` + `client.src.js` 构建） | 读取侧栏看到的同一份会话列表，计算顺序，并通过官方 `workspaces.insertBefore` 应用；同时负责两处 DOM 增强 |
| `lib/order.cjs` | 纯排序逻辑（含 `orderFor` 的模式分派） |
| `lib/menu.cjs` | 纯 UI 决策（该不该显示、行键解析、弹层定位、文案），让 DOM 层保持极薄 |

这样设计的原因：浏览器半侧已经持有**与侧栏完全一致**的 `updatedAt`，排序键
不可能与用户看到的时间漂移；宿主半侧因此零依赖（只用 Node 内置模块，不
import 任何 `@deepseek-ai/*`）。

宿主状态每 15 秒被浏览器半侧重新读取一次（外加窗口重新获得焦点时），用于收敛
带外改动（手改 `state.json`、第二个窗口）。该轮询**不会**自行触发重排：只有模式或
置顶集合真的变化时才会重新应用顺序，因此不会打断手动拖拽。

## 运行时诊断

浏览器半侧每次完成一轮界面处理，都会把**实际结果**回报到宿主（内存中，不落盘）：

```bash
curl -s -X POST http://127.0.0.1:19387/workspace-sort/api/diagnostic -d '{}'
# -> { ok: true, value: { receivedAt, report: {
#        viewOptions: 'injected' | 'already-present' | 'menu-closed' |
#                     'hidden-for-mode' | 'menu-shape-unexpected' | 'error',
#        rowPins: <装饰成功的工作区行数>,
#        panelSlot: <底部按钮是否注册进官方 slot>,
#        rowMenuInstalled, panelOpen, mode, ready, language } } }
```

用途：DOM 单元测试跑的是对原生标记的**重建**，只有运行中的窗口能证明插件匹配到了
真实结构。`viewOptions` 长期停留在 `menu-shape-unexpected` 或 `rowPins` 为 0，
就说明该 DSH 版本的侧栏结构与插件预期不一致（此时底部面板仍然可用）。

## 状态文件

```
$DSH_HOME/workspace-sort/state.json        # 默认 ~/.dsh/workspace-sort/state.json
{
  "version": 1,
  "sortMode": "manual",                    // manual | updated
  "pinned": ["<workspaceId>", "..."]
}
```

文件损坏时会备份为 `state.json.corrupt-<timestamp>` 并以默认值启动，不会阻止
插件挂载。本插件**从不**删除工作区、会话或任何文件，只调用
`workspaces.insertBefore` 改变顺序。

## 开发

```bash
node build.cjs     # 由 lib/order.cjs + lib/menu.cjs + lib/client.src.js 生成 lib/client.js
npm test           # 先构建，再依次运行五个测试文件
```

- `test/order.test.cjs` — 纯排序逻辑（含 4 个工作区全部 576 种排列的
  `minimalMoves` 性质测试，以及模式分派与置顶分区）。
- `test/menu.test.cjs` — 纯 UI 决策（显示条件、视图状态解析、行键解析、弹层夹取、文案）。
- `test/controller.test.cjs` — 把**真正的**浏览器半侧源码放进 VM，对着假的
  `sessions` / `workspaces` 服务与假路由跑完整控制器（含手动拖拽保护、模式切换、
  置顶、轮询收敛与降级）。
- `test/ui.test.cjs` — 用 `test/dom.cjs`（一个只实现所需表面的极小 DOM）对
  **真实的**菜单注入、右键菜单、行尾图钉与底部面板断言生成的元素树，并用一个
  假 React 断言 footer slot 的注册形状。侧栏没有为视图选项菜单提供插槽，所以这是唯一
  能在没有浏览器的情况下验证「分组是否插到了正确位置」的方式。
- `test/host.test.cjs` — 用 `DSH_HOME` 指向临时目录导入真正的宿主半侧，
  驱动它自己的 HTTP handler（含 fence 与损坏文件恢复）。

浏览器半侧是**手写**的模块加载器 bundle（产物是经典脚本，不是 ESM），所以
构建不需要 tsdown / rolldown / typescript 或 `pnpm install`。`build.cjs` 会在
写盘前用 `vm.Script` 编译一次，语法错误在构建期就失败。

## 安装

profile（如 `desktop`）可用两种方式挂载：

1. GUI：侧栏「插件 → 添加插件」，填入本地绝对路径；
2. 手动：把本包放入 profile 的 `node_modules`，并把它加入 profile
   `package.json` 的 `dsh.profile.bundles`。

`cordis.patch.yml` 会 `insert` 一行 `id: workspace-sort`。

## 卸载

停用或移除该 bundle 即可停止排序；删除 `state.json` 清除排序模式与置顶。
已有工作区顺序原样保留。

## 已知限制

- 排序只在**同级**工作区之间生效。树形分组下子工作区无法超越其祖先。
- 未分组（Ungrouped）是派生分组，固定在所有工作区之后，不属于本插件管理范围。
- 平铺（单列表）模式没有工作区行，顺序在该模式无视觉影响，因此也不显示排序方式控件。
- 自动排序只在窗口打开时运行（顺序本来就是界面里的呈现）。
- 视图选项菜单与工作区行图钉没有官方插槽，所以是 DOM 增强：DSH 升级若改变菜单或行
  结构，最坏结果是这些控件消失，原生界面、右键菜单、**底部面板**与排序逻辑都不受影响。
